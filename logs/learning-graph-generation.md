Date: 2026-07-06

Grade 1, Grade 2, Grade 3, Grade 4, Grade 5, Grades 6-8, Grades 9-12 — producing

## Why the skill needed adaptation

`SKILL.md` hardcodes `docs/course-description.md` as its source and
`docs/learning-graph/` as its output directory, and assumes a single run per
project. Every one of the 8 runs in this session substituted:

- Source: `docs/bands/<band-slug>/course-description.md` instead of
  `docs/course-description.md`
- Output: `docs/bands/<band-slug>/learning-graph/` instead of
  `docs/learning-graph/`
- The skill's python scripts (`analyze-graph.py`, `csv-to-json.py`,
  `taxonomy-distribution.py`, `add-taxonomy.py`) plus
  `learning-graph-schema.json` and `index-template.md` were copied fresh into
  each band's `learning-graph/` directory (8 copies total), matching the
  skill's own Step 0 instruction to work from a local copy.
- `index.md`'s course-description link was set to `../course-description.md`,
  which resolves correctly one level up from each band's `learning-graph/`
  into that same band's directory.
- The site-wide `docs/learning-graph/index.md` placeholder was never touched
  and remains exactly as `init-textbook` scaffolded it — confirmed at the end
  of this session.

## Taxonomy scheme

A consistent 7-category taxonomy was used across Kindergarten through Grade 5
(`FOOD`, `GROW`, `EMOT`, `WELL`, `SAFE`, `SKIL`, `FOUND`), so the same color
and category scheme is comparable across bands in a future graph viewer. At
Grades 6-8 and 9-12, an 8th category (`SUB` — Substance Use Awareness and
Prevention) was added for the strand that first appears at that band, and
`GROW` was relabeled "Human Growth, Development, and Sexual Health" to
reflect the Sexual Health content added there. `SKIL` (Skill Standards) has
the largest raw benchmark count at both large bands (~20 each) and was
explicitly checked against the 30%-of-total balance ceiling each time; it
landed at 18.8% (Grade 6-8) and 27.2% (Grade 9-12) — both under the ceiling,
so it was kept as a single category rather than split.

## Process: one subagent per band, always independently re-verified

Each band was generated by a single dedicated subagent (Agent tool,
general-purpose), briefed with the full path overrides, concept-count target,
taxonomy guidance, and an explicit instruction to do all the work
synchronously rather than reporting completion prematurely. After every
subagent reported back, the coordinating session independently re-verified
before wiring anything into the site:

- Re-ran `analyze-graph.py` on the submitted `learning-graph.csv` and diffed
  the output against the subagent's own `quality-metrics.md` — required to
  be identical.
- Checked `concept-list.md`'s numbered-entry count against
  `learning-graph.csv`'s data-row count against `learning-graph.json`'s node
  count — required to match across all three.
- Checked every CSV row has a non-empty `TaxonomyID`.
- Checked every JSON edge references a valid, unique node id.
- Only after all of the above passed was the band wired into `mkdocs.yml`
  nav, `mkdocs build --strict` re-run, and the band's files committed.

This caught two real problems (see below) that a self-report alone would have
missed.

## Problems encountered and how they were resolved

### Kindergarten: false completion report + a genuine write race

The first subagent call for Kindergarten reported the task complete after
only 4 tool calls and 39 seconds — implausibly fast for a full learning-graph
run. Checking the directory directly showed it had only copied the python
scripts (Step 0) and written nothing else. It was resumed with an explicit,
numbered list of the exact remaining steps and a direct instruction not to
report completion until every file existed on disk.

On the resumed run, the agent's own report disclosed that a second,
independent background instance of the same task had apparently been
running concurrently and was overwriting `concept-list.md`,
`learning-graph.csv`, `concept-taxonomy.md`, and `taxonomy-names.json` with a
divergent version — a genuine race condition, not a hallucination. The agent
sent a stop message to the other instance and did a final clean rewrite. A
few minutes later a task notification arrived from that second, independent
agent instance, which had itself investigated the collision, verified the
first agent's final file state was correct, and stood down rather than
re-clobbering it. Both reports converged on the same final numbers (45
concepts, 7 categories), which was then independently confirmed a third time
by the coordinating session's own verification pass (identical
`analyze-graph.py` re-run, matching node/edge counts). Net effect: the final
files on disk were correct and triple-verified, but getting there took two
extra round-trips. This is a platform-level concurrency quirk to watch for
on any future multi-band or multi-agent regeneration, not a mistake in the
skill or the course-description content.

### Grades 6-8: two backend connection drops mid-run

The Grade 6-8 subagent's connection was cut off mid-response twice
(`API Error: Connection closed mid-response`), after 14 and then 18 tool
calls respectively. Each time, rather than assuming failure, the disk state
was checked directly:

- After the first drop: scripts copied, `concept-list.md` (133 concepts,
  on target) and `concept-taxonomy.md` (8 categories, all under 30%,
  quality score 92/100) were complete and high quality. The agent was
  resumed with an explicit list of only the remaining steps (3-12).
- After the second drop: everything through `learning-graph.json` and
  `taxonomy-distribution.md` was complete and independently verified
  (identical `analyze-graph.py` re-run, valid node/edge integrity). Only
  `index.md` and the session log were missing. Rather than risking a third
  connection drop on a resume, the coordinating session wrote those two
  files directly — both are template-substitution / structured-summary work
  that doesn't require re-deriving content, so this carried no quality risk.

### A user commit landed mid-session

Partway through wiring Grade 6-8 into `mkdocs.yml`, `git status` showed the
band's 18 generated files already committed under commit `86a9dde
"Generating learning graphs"`, authored as the human user rather than
through any tool call in this session — apparently committed manually from a
separate terminal while the agent work was in flight. This was surfaced to
the user rather than silently reconciled; the remaining `mkdocs.yml` nav
change was committed separately on top.

## Known pre-existing issue (not introduced by this session)

`learning-graph-schema.json`, as shipped in the skill package, expects
`groups.<ID>.color` to be a nested object, while `csv-to-json.py` (v0.04,
also shipped in the same skill) emits `color` as a flat CSS color-name
string — matching SKILL.md's own documented examples. This mismatch is
in the shared skill package itself and was present identically across all 8
runs; it does not affect the vis-network graph viewer, which consumes the
flat format. Worth fixing upstream in the skill package at some point, but
out of scope for this site.
